## Работа без остановки после одного PR

Прямое правило владельца: **не останавливаться после одного PR, если в текущем запуске есть время на следующий безопасный шаг**.

1. Читать этот план, свежие current_task/state, AGENTS, OWNER_PRIORITY и комментарии #996/#1334; сверять release/main, открытые рабочие PR и выполняющиеся CI/deploy.
2. Завершать начатый полезный пакет или брать ближайший независимый пункт. Не повторять завершённое, не дублировать чужую работу, не force-push.
3. Один финальный build/CI-цикл на связный source-пакет. Красный обязательный CI исправлять в том же PR; красный код не интегрировать.
4. После зелёных применимых проверок интегрировать в release; успешный source artifact переиспользовать. Документация не требует asset rebuild, браузера или deploy.
5. Готовый значимый визуальный пакет публиковать штатным exact artifact в isolated whole-site preview; коротко проверять изменённые состояния.
6. Записывать точные code/release/preview SHA, пользу, изменение веса, проверенное/deferred и конкретный следующий шаг в состоянии и #996; #1334 хранит сводку.
7. Пока есть время, сразу переходить к следующему безопасному шагу в этом же запуске. Завершённый PR, ожидание production-приёмки и один заблокированный пункт не являются причиной остановки.
8. При блокере записывать точную причину и брать независимую задачу. Не обходить отказы инструментов/права, обязательные проверки или защищённые контракты; не тратить запуск на повтор одинаковых проверок.
9. Завершать запуск при исчерпании доступного ресурса, выполненной очереди либо отсутствии безопасной доступной задачи. Сохранить точку продолжения.

Ежечасное расписание возобновляет работу между запусками. Это не бесконечный один процесс: внутри запуска продолжается следующий безопасный шаг, после окончания ресурса сохраняется состояние для следующего. Обновляется существующая автоматизация, вторая для той же задачи не создаётся.

## Критерии новых полезных пакетов

1. Конкретный подтверждённый дефект либо согласованный пользовательский сценарий.
   Главный путь: форма → выдача → конкретный тур → параметры/рейсы → сводка → форма заявки.
2. Один актуальный владелец компонента. Использовать удачные компоненты прежнего
   оформления как доноры, адаптируя к текущей разметке; убрать заменённые правила,
   обработчики и подключения в том же пакете. Новые decorators/override-слои не добавлять.
3. Рост CSS/JS разрешён ради визуала, адаптива, доступности или функциональности.
   Отчёт initial/full/inline честный; перенос кода и lazy-loading не считать удалением.
   Жёсткий12KB/нулевой рост и обязательная экономия каждого пакета не являются целью.
4. Общие локальные фильтры оценивают питание/бюджет на одном предложении; неполные
   фасеты скрываются/сбрасываются. Сохранить original items, lifecycle/generation,
   progressive counts, сортировку/возврат, источник и конкретный search context.
5. Один результат по принятому local ID; новые связи по названию/цене не создавать.
   Сбой одного поставщика не скрывает другие результаты. Не выдумывать рейсы,
   багаж, конечную цену/сборы, часы работы, legal/payment и маркетинговые обещания.
6. SOURCE → узкая необходимая проверка → применимые Security/owner/artifact guards.
   Использовать проверенный source artifact при интеграции; docs-only без build/browser/deploy.
   Затронутую визуальную область проверить соразмерно; физический Safari/прочее
   непроверенное обозначать deferred. Красное не считать passed.
7. Только штатный isolated whole-site preview из актуальной release; происхождение,
   noindex, disabled production leads, counter0, rollback и fingerprints сохранить.
   Main/production, protected API/Tourvisor URL-payload, price arithmetic, lead transport/
   field mapping, Метрика/goals, логотип и соседние проекты не меняются этим допуском.
8. SEO архитектура/аудит #1720 разрешены параллельно. Массовая генерация и изменения
   production indexation/robots/canonical/redirects/sitemap требуют отдельного плана/допуска.
