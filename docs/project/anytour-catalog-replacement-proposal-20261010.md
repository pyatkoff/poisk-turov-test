# LOCAL: постоянный каталог увиденных отелей Tourvisor

Дата: 10.10.2026. Статус: **SOURCE_IMPLEMENTED / RUNTIME_NOT_ACTIVATED**.
PR: [#4500](https://github.com/pyatkoff/poisk-turov-test/pull/4500).
Основа: release `204321402c4350f9b79ae24f7493387602239af6`.

Реализация следует новому ТЗ владельца: **новый LOCAL ID равен Tourvisor ID**.
Предыдущий вариант этого документа с собственными новыми ID заменён этим решением.
Реальная миграция, наполнение и переключение NEXT ещё не выполнены. Изолированные
SQL/API/UI fixtures не доказывают готовность развёрнутого каталога.

## Регистрация и восстановление истории

`local_tv_hotels.id` — исходный положительный Tourvisor ID, без нового номера.
Сервер `api-v2.php::tourvisor_autosave_results()` регистрирует все уже полученные
реальные строки до отбора предложений. Общий `price-observer-v1.php` делает то же
для реальных поисков и мониторинга до прежних лимитов ценовых наблюдений.
Не нужны открытие карточки, заявка, популярность, полное описание или подходящая цена.
Повтор меняет только `last_seen_at`, сохраняя возраст backlog и всё содержимое.
CI/demo контексты исключены; включение контролирует серверный флаг.

Первоначальный backfill использует сохранившиеся `tour_price_observations`,
`hot_tours_current`, а при наличии — `tour_operator_identity_observations`,
`anytour_offers` и `anytour_offer_price_observations`. Дополнительные offer-источники
берутся только для `provider=tourvisor`: native ID другого поставщика не TV ID.
Нет ограничения свежестью, страной, ценой, кликами или top-N. Словарь `catalog_hotels`
и одни лишь mappings не являются доказательством появления в реальном поиске.

Удаление ценовой истории не удаляет уже зарегистрированный LOCAL или его очередь.
Очистка истории до внедрения, прежние лимиты наблюдений и несохранённые результаты
ограничивают восстановимое покрытие. Отсутствие исторического demo-маркера тоже нельзя
ретроспективно исправить догадкой. Реестр содержит **восстановленные наблюдения**,
а не обещание всех когда-либо существовавших результатов.

## Суточное наполнение и сохранность

Единственный суточный владелец — существующий `collect-hotel-details-v1.php` и его
workflow, с прежним cron. При включённом серверном флаге запуск без явного scope
использует `local`; выключенный флаг сохраняет прежнее поведение. Новый cron,
платный поиск туров и отдельный TV-адаптер не созданы.

Сборщик последовательно выполняет backfill, перенос подтверждённых связей и наполнение.
Незавершённые строки идут FIFO по первому обнаружению; затем обновляются устаревшие
успешные карточки. Повторный поиск не поднимает недавно увиденный отель над старым
остатком. Доступный полный `catalog_hotel_details.raw_json` с правильными hash/ID/time
используется первым. Старый retained ответ не подменяет необходимое обновление.
Иначе используется прежний `/hotels/{id}` с прежними auth/retry/quota/spacing границами.
MySQL advisory lock исключает два одновременно работающих LOCAL-сборщика.

Одна транзакция сохраняет полный decoded JSON ответа, hash, fetched time, нормализованные
поля, ревизию и состояние. Полная безопасная галерея не ограничена прежними 100 фото;
порядок и подписи остаются в `photoDetails`, исходные поля — в `source_json`.
Сохраняются общий текст, дополнительные текстовые разделы, инфраструктура, услуги,
питание, номера, координаты и прочие содержательные поля карточки.

| Состояние | Поведение |
| --- | --- |
| `pending` | Уже обнаружен; ещё не обработан или отложен лимитом |
| `retry` | Ошибка отдельного отеля; следующая попытка не раньше следующего дня |
| `ready` + `sourceAbsent` | Источник успешно получен; перечисленных полей в нём нет |
| Ошибка/пустой/wrong-ID ответ | Хорошее содержимое не очищается; остальные отели продолжаются |
| COMMIT/readback неизвестен | Запуск останавливается с UNKNOWN; слепого повторения нет |

Пустые/отсутствующие листья нового ответа не стирают хорошие значения. Ручная защита
хранится по полю, включая вложенные поля; она не блокирует наполнение всей карточки.
`setManualFields(id, fields, expectedRevision)` — только privileged библиотечный метод,
с проверкой ревизии, без публичного HTTP writer. Намеренно пустое ручное значение
отличается от отсутствующего поля источника и также показывается в NEXT.
Отчёт разделяет discovered/ready/unfinished, ошибки, sourceAbsent, retained/fetched
источники и остаток, отложенный квотой. `ready` не означает наличия каждого поля в источнике.

## Старые ID, MATCH и зависимости

Старый собственный `anytour_hotels.id` остаётся отдельным namespace. Он не приравнивается
численно к TV ID. `local_tv_legacy_links` переносит только подтверждённый
`anytour_hotel_sources.namespace=legacy_catalog` old→TV edge для зарегистрированного TV ID.
Несколько TV ID у старого отеля, несовпадающий hash или конфликт ручных полей дают
явную проблему переноса. Совпадение названия/числа не используется.

Сохраняется snapshot старого profile JSON/hash/revision/active и всех его source records,
включая подтверждённые provider/MATCH evidence. Старые таблицы, FK, mappings, отказные
решения, rooms/meals, offers, URL и избранное остаются на своих прежних идентичностях.
Их сохранение не означает новой активации или acceptance. Есть post-COMMIT readback;
повтор идентичного переноса не меняет данные, изменение старого профиля требует review.

Известный seed и проверяемые enrichment receipts определяют импортированные поля.
Изменённые и недоказанные листья защищаются отдельно как ручные. Поэтому ручное описание
не замораживает автоматически полученную галерею. При неполной provenance сохранность
имеет приоритет; такие поля не перезаписываются догадкой.

## Чтение в NEXT

`local-tv-catalog-read-v1.php` — GET-only, no-store, только LOCAL/NEXT preview paths.
Запрос задаёт ровно один namespace: `tourvisorHotelIds[]` или `oldLocalHotelIds[]`.
DTO отдаёт ID/revision/content state, безопасное содержимое и точные links/missing IDs.
Raw/source/private snapshot и предложения не выходят через этот endpoint.

В существующем `prototype-search/data.js` включаемое чтение дополняет presentation
через подтверждённую old→TV связь. Совместимый ID выбранного предложения остаётся старым
own ID; новый content ID доступен как `raw.localHotelId`. Это два явных namespace.
Карточка и подробности получают одно LOCAL-содержимое. Повторное открытие перечитывает
сохранённую ревизию без поиска туров. Ограничены параллельность, batch и timeout;
чужие links, конфликт ревизии и ответы старой search generation не применяются.
Ошибка reader сохраняет уже показанное содержимое. Состав предложений, их ID/цены,
fuel/flight receipts, lead/Metrika и основная production-версия не меняются.

По умолчанию browser rollout выключен: `V2_CONFIG.localTvCatalogEnabled !== true`.
Новый код не переключает текущий NEXT автоматически.

## Проверка и граница дальнейшего исполнения

`tests/local-tv-catalog-test.php` выполняет настоящие SQL и локальный HTTP reader
на disposable fixture. Тот же тест запускается с MySQL8 в существующем canonical CI.
Проверяет историю, FIFO, ошибки/квоту, unlimited gallery/captions, ручные листья,
сохранение старых профилей/source evidence, ambiguity, namespaces и потерю COMMIT ACK.
`tests/local-tv-catalog-browser.cjs` использует DTO, полученные этим HTTP reader,
проверяет настоящий adapter и compiled NEXT на 360/390/430/768/1280, новую ревизию
при повторном открытии, неизменность предложений и отсутствие нового поиска туров.
Все supplier responses в UI tests вымышленные; deployed NEXT ими не проверен.
Результаты конкретных запусков и exact source SHA фиксируются в PR и #4217.

До реального включения нужны проверенный backup/состав переноса, текущий crosswalk,
решение по ограничениям #4191, review точной схемы и допуска writers, согласованная
остановка прежних authoritative content writes и проверяемый порядок rollout:
схема → registry/server flag → текущая суточная очередь → API → browser flag → NEXT.
Схема не устанавливается автоматически; endpoint нельзя использовать для наполнения.

Workflow разрешает фактический scope до первого writer. В новом local режиме
не запускаются прежние migrate-hotel-details-v1.php и build-seo-offer-snapshots-v1.php;
они сохраняются для demand/canonical. Расписание с включённым LOCAL-флагом также
выбирает эту ветку; ошибка чтения флага останавливает запуск до записи. Само чтение
флага не подключается к БД и не печатает private config. Ограничение limit действует
на наполнение карточек; восстановление истории и перенос связей перед ним охватывают
весь сохранившийся список и должны отдельно входить в рассмотренный scope запуска.

**STOP 6047119931 и phase3 UNKNOWN/no-replay сохраняются для прежних операций.**
Новый LOCAL имеет собственный путь записи: только local_tv_hotels и
local_tv_legacy_links; старые profiles/sources читаются для подтверждённого переноса,
не перезаписываются. Это основание отдельного review нового запуска, а не общий
запрет на разработку нового каталога. Допуск к реальным данным устанавливается по
проверенным target, writer, составу переноса и сохранности данных; одно новое имя
таблицы его не доказывает. Прежние остановленные операции не повторяются,
нулевой эффект UNKNOWN не заявляется, platform refusal не обходится.
Предыдущие 537 canonical profiles / 5133 поля — исторический результат, а не число
заново полностью наполненных LOCAL-отелей. Реальные новые счётчики здесь не заявлены.

Приёмка ещё требует фактических реестра/наполнения/остатка в БД, API parity и сохранённого
содержимого в развёрнутом NEXT на desktop/mobile. PR, CI и расписание по отдельности
не закрывают эту приёмку. Старый каталог не удаляется; rollback не стирает новые данные.
